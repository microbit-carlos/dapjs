Times every USB transfer dapjs makes to a DAPLink board (BBC micro:bit V1 or V2) and lets the same board be driven over WebUSB bulk endpoints, WebUSB control transfers on endpoint 0, or WebHID interrupt endpoints. Results stay in the page: keep DevTools closed while timing, then download or copy them. Nothing is sent anywhere.

Device

No device 
Pick a transport and connect. The board does not need a program on it; nothing is flashed until you ask.

If claiming the interface fails on Windows, chrome://device-log says which driver is bound to it (WinUSB is needed). A V2 in control-transfer mode uses its zero-endpoint WebUSB interface, the same one a V1 uses, because the firmware only answers SET_REPORT/GET_REPORT on that interface number.

Transfer micro-benchmarks (no flashing, no SWD)

With control transfers the firmware runs the DAP command inside the SET_REPORT handler, before it answers the status stage, so OUT time includes command execution and IN time does not. With bulk or interrupt endpoints the OUT completes as soon as the packet is received and the IN waits for the reply.

Flash

A page limit leaves the target with a partial program, which is fine for timing, and the CLOSE command may then report an error even though every per-page timing is valid. After a Stop the board may need unplugging before it accepts another flash. The same hex file should be used for every machine you compare; the summary records its size and page count.

Results

The report so far, exactly as Copy report and Download report give it. It updates while a test runs, so it can be sent at any point: on a slow machine a few minutes of a run is usually enough.
